站点的 `/memory` 页分两块:**PHOTOS.** 摄影图集和 **GAME LOG.** 游戏记忆。
两块都是构建期读文件生成,不连数据库——往仓库里放东西就行,部署后自动出现。

## 一、发照片(PHOTOS.)

规则只有三条,零配置:

1. 图片丢进 `public/photos/`,**子文件夹名 = 分组名**;
   不建文件夹直接放根目录会归入 "ALL" 组
2. **文件名(去掉扩展名)= 图片说明**,所以起名像人话一点:
   `2026-10-20-外滩夜色.jpg` 显示出来就是 `2026-10-20-外滩夜色`
3. 推荐日期前缀命名(`YYYY-MM-DD-描述`):同组内按文件名**倒序**排列,
   日期前缀让新图自动排最前

目录长这样:

```
public/photos/
├── 街拍/
│   ├── 2026-10-12-neon.jpg
│   └── 2026-10-03-cross.jpg
└── 风景/
    └── 2026-10-20-dusk.jpg
```

支持 `jpg / jpeg / png / webp / gif / avif / svg`,**HEIC 不在列**
(iPhone 传图时选"转换为兼容格式")。

两个小建议:

- 长边压到 2000px 左右再上传,手机原图 5-8MB,网页加载会慢
- 分组文件夹名避免空格和 `# ? %` 这类符号

点任意缩略图会打开全屏灯箱:`Esc` 关闭、`←/→` 切换、能跨分组连着翻。

## 二、写游戏记忆(GAME LOG.)

一条记忆 = `content/memories/` 下的一个 `.md` 文件,模板:

````markdown
---
date: 2026-11-01
game: 明日方舟
friends: [阿米娅, 小舟]
images: [screenshot1.jpg]
---

那天我们清空了主线第三章,辅助拉满。
下次目标:危机合约。
````

字段说明:

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `date` | 建议 | `YYYY-MM-DD`,按它倒序;不写会沉底并显示"日期未填" |
| `game` | 可省 | 游戏名;一次玩多个写数组 `game: [明日方舟, 双人成行]` |
| `friends` | 可省 | 同行的朋友,显示成"与 阿米娅、小舟" |
| `images` | 可省 | 截图文件名,**相对 `public/memories/`**,图先放进那个文件夹 |
| 正文 | — | `---` 之后随便写,换行保留 |

文件名随意(建议同样日期前缀),它不会出现在页面上。

时间线左侧的方块节点、游戏胶囊和"与 XX、XX"都是自动生成的,
图片同样点开灯箱查看。

## 三、生效方式

本地 `npm run dev` 保存即见(图片可能需要强刷 `Ctrl+Shift+R`);
线上 commit + push 触发重新构建后生效。

仓库里自带的示例(占位 SVG 和两条示例记忆)看完本篇就可以删了。
